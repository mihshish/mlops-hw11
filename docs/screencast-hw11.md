# ЛР 11: сценарий скринкаста без озвучки

Опыты A/B/C и пять Kubernetes-проверок уже выполнены. Для записи используй результаты в `report.html` и два коротких живых вызова — `make hw11-status` и `make hw11-smoke`. Повторять замеры не нужно.

Ориентир — около 6 минут. В задании нет фиксированного требования к длительности ролика. Все длинные прогоны и загрузки выполняются **до** записи. Не держи зрителя 120 секунд на каждом из 12 повторов.

## До записи

1. Открой папку `C:\MLOPS\11\mlops-hw11` в VS Code: File → Open Folder.
2. Terminal → New Terminal → стрелка возле плюса → Git Bash.
3. Docker должен работать в фоне; окно показывать не нужно. Выполни `make hw11-status`: у api должно быть `2/2`, у Prometheus и Grafana — `1/1`. Если Docker остановлен, сначала запусти его и дождись готовности. Не выполняй `make hw11-down` перед записью.
4. Двойным кликом в проводнике открой локальный `report.html` в браузере. В отдельном терминале запусти `make hw11-grafana` и оставь его открытым. В браузере открой `http://127.0.0.1:3000/d/hw11-observability`. История метрик в Grafana живёт ограниченное время: если ночных точек уже нет, показывай **сохранённый график** из отчёта, а в Grafana — текущие Ready и CPU/RAM. Не переснимай или не выдавай текущие точки за старый замер.
5. В VS Code подготовь одну вкладку `hw11/chart/values.yaml`. Все исходники открывать не надо. Отключи микрофон, увеличь шрифт.

## В кадре

1. **Стенд (0:00–0:55).** Покажи values: 2 реплики, версия, 20 с прогрева, CPU/RAM. В терминале — `make hw11-status`, чтобы были видны живые Pod и EndpointSlice.
2. **Прогрев и обновление (0:55–2:10).** В отчёте покажи график A и строки 20/61 → 0/61 запросов до прогрева. Далее — штатный выкат: 105 полных ответов, ноль 5xx и обрывов, длинный поток на 30 частей. Bad B не стал Ready, после отката ответы A. Принудительный обрыв на 4-й части — отдельный ожидаемый опыт.
3. **Горячая реплика (2:10–3:25).** Покажи график по Pod и сравнение политик за три повтора. При перекосе 80%: 563 отказа из 2400 с привязкой, 2 из 2400 без неё. Покажи и контрпример: равномерный повтор с ClientIP 400/400.
4. **HPA и Grafana (3:25–4:50).** Покажи 2→3→2 на сохранённом графике и таблицу создания/готовности Pod. Затем строки двух алертов: pending → firing → inactive. В живой Grafana достаточно текущих панелей TTFC, running/waiting и Ready; если историю уже очистил retention, не ищи её в кадре. Это фрагменты ответа, не токены.
5. **Живой ответ и проверки (4:50–5:40).** Отправь один запрос из реального клиентского Pod:
   ```bash
   make hw11-smoke
   ```
   Покажи `completed`, `backend_mode=simulated`, имя Pod, версию и число частей. Для короткой сверки сохранённых результатов можешь выполнить `make hw11-audit` — без повторного rollout и нагрузки.
6. **Итог (5:40–6:15).** Покажи короткое ревью PR из отчёта: B свободен, 0,8 с меньше 3 с очереди на A, а уже начатый поток не переносим. Заверши ссылкой на GitHub и каталогом results.

Перед отправкой проверь, что видно: до/после прогрева, штатный и аварийный исходы, три повтора политик, реальные HPA/алерты, один HTTP-запрос и ссылка на отчёт. Рассказ голосом и карточки не нужны.
