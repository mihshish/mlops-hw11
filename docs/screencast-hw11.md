# ЛР 11: сценарий скринкаста без озвучки

**Сначала закончи A/B/C и получи реальные результаты в Kubernetes.** На момент первой попытки свободное место закончилось во время развёртывания, поэтому сейчас это план показа, а не подтверждение готового стенда. Не снимай локальные 7 тестов как демонстрацию Kubernetes.

Ориентир — около 6 минут. В задании нет фиксированного требования к длительности ролика. Все длинные прогоны и загрузки выполняются **до** записи. Не держи зрителя 120 секунд на каждом из 12 повторов.

## До записи

1. Открой папку `C:\MLOPS\11\mlops-hw11` в VS Code: File → Open Folder.
2. Terminal → New Terminal → стрелка возле плюса → Git Bash.
3. Docker должен работать в фоне; окно показывать не нужно. Запусти `make hw11-up`, если стенд ещё не запущен. Затем последовательно выполни A/B/C, verify, collect и report по README.
4. Подготовь браузер: открытый локальный `report.html` и Grafana. Для Grafana запусти в отдельном терминале `kubectl --context kind-mlops11 -n hw11 port-forward svc/grafana 3000:3000`. Открой `http://127.0.0.1:3000/d/hw11-observability`. Выбери интервал опытов по времени.
5. В VS Code подготовь одну вкладку `hw11/chart/values.yaml`. Все исходники открывать не надо. Отключи микрофон, увеличь шрифт.

## В кадре

1. **Стенд (0:00–0:55).** Покажи values: 2 реплики, версия, 20 с прогрева, CPU/RAM. В терминале — `make hw11-status`, чтобы были видны живые Pod и EndpointSlice.
2. **Прогрев и обновление (0:55–2:10).** В отчёте покажи график A и две строки сравнения: в сломанной версии был запрос до прогрева, в исправленной нет. Покажи, что долгий поток пересёк rollout и дошёл до конца; bad B не стал Ready, после отката ответы A. Принудительный обрыв — отдельный, ожидаемый опыт, не часть безошибочного rollout.
3. **Горячая реплика (2:10–3:25).** Покажи график по Pod и сравнение политик за три повтора. Обрати внимание на число запросов в Pod, p95 TTFC и очередь. Если ожидаемого перекоса не было в отдельном прогоне — покажи и его, с причиной по IP/раскладке.
4. **HPA и Grafana (3:25–4:50).** Покажи 2→3→2, когда третья реплика создана и когда стала Ready. В Grafana покажи TTFC, running/waiting, два алерта и возврат в норму. Не называй части ответа токенами.
5. **Живой ответ и проверки (4:50–5:40).** Отправь один запрос из реального клиентского Pod:
   ```bash
   kubectl --context kind-mlops11 -n hw11 exec load-0 -- python -m lab11.client --single --run screencast
   ```
   Покажи `completed`, `backend_mode=simulated`, имя Pod, версию и число частей. Открой результаты пяти проверок в отчёте; не делай второй rollout специально ради видео.
6. **Итог (5:40–6:15).** Покажи короткое ревью PR из отчёта: B свободен, 0,8 с меньше 3 с очереди на A, а уже начатый поток не переносим. Заверши ссылкой на GitHub и каталогом results.

Перед отправкой проверь, что видно: до/после прогрева, штатный и аварийный исходы, три повтора политик, реальные HPA/алерты, один HTTP-запрос и ссылка на отчёт. Рассказ голосом и карточки не нужны.
