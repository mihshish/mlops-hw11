Это не заявление о прохождении baseline всех behavioral-тестов кандидата.

## Команды на этом ноутбуке

VS Code → Open Folder → `C:\MLOPS\8-9-10\hw8910-broken`.
Терминал Git Bash, все команды из корня с Makefile:

```bash
make install           # uv sync --frozen --extra inference, один раз
make check             # 44 быстрые проверки без модели
make check-red         # семь исходных дефектов -> семь исправленных проверок
make ci-negative       # ожидаемый Error 1: дефект в изолированной копии кода
make process-demo      # лёгкие сбои, кеш, повтор, согласование журнала
make flow-demo         # настоящие Prefect runs на STUB, несколько минут
make rollback-demo     # настоящий HTTP A -> B -> A на STUB
```

Настоящие артефакты уже подготовлены в `.runtime/real` (не в Git).
В новом рабочем каталоге на этом ноутбуке, при работающем MLflow ДЗ 6+7:

```bash
make import-hw67        # читает прежние артефакты; не обучает модель
make real-flow-demo     # сбой/восстановление, baseline, повтор, отказ кандидата
```

`import-hw67` — **инициализация**, а не команда для каждого скринкаста:
она заново создаёт локальный указатель baseline. Для обычного повторного
проверяемого выпуска используйте `make release-baseline`.

Запуск API в отдельном терминале (один процесс, без --reload):

```bash
make serve
```

Во втором терминале:

```bash
make status            # health 200; ready сначала 503, затем 200
make smoke             # настоящий ответ, совпадающий с сохранённым baseline
make invalid           # 422 и неизменный счётчик вызовов
make bench             # 4 одинаковых запроса при concurrency=1, затем те же 4 при 2
```

API: <http://127.0.0.1:8091/docs>. Если порт уже занят нашим готовым сервисом,
не запускайте второй экземпляр: выполните `make status`.
Модель загружается один раз при старте. Изменение accepted.json без перезапуска
не изменяет модель в памяти. Остановка foreground-сервиса — Ctrl+C, затем
повторный `make serve`. Окно Docker для показа API не требуется.

Короткий показ сохранённых тяжёлых опытов (это явно **не новый запуск**):

```bash
make flow-proof
make rollback-proof
make bench-proof
```

## Воспроизведение на другом компьютере

Python 3.12 + uv; `uv sync --frozen` достаточно для быстрых проверок.
Для настоящей модели нужны `uv sync --frozen --extra inference`, несколько ГБ
памяти для модели/библиотек и исходные веса. На 8 ГБ закрывайте лишние приложения;
при подкачке загрузка и первый ответ могут занять минуты.

`upstream` содержит полный golden/train index, сырые ответы, eval-код и хеши,
но **не веса**. Baseline публична на Hugging Face по точной ревизии;
восстановление только принятой baseline без MLflow: `make restore-baseline`.
Этот режим не заявляет загрузку недоступного адаптера кандидата.
Для полного повтора obtain/reject кандидата нужен MLflow из ДЗ 6+7
(run `8b9e58ba729642a0847ac4ec564f3cbb`, artifact `model/artifacts/adapter`)
и `scripts.import_hw67 --source <путь к прежнему проекту>`.
При локальной защите этот артефакт доступен в MLflow; веса намеренно не публикуются.

Локальные пути в manifest — снимок данного ноутбука. На другой машине
восстановление пересчитывает реальные файлы и меняет только пути;
model/runtime/golden/protocol-хеши должны совпасть с закреплённым inventory.

## Автоматизация

[`ci.example.yml`](ci.example.yml) — исходный шаблон преподавателя.
Исполняемый workflow — [`.github/workflows/quick.yml`](.github/workflows/quick.yml).
Локальные зелёный и намеренно красный прогоны сохранены в evidence.
Защита merge не настраивалась и не заявляется. Результат удалённого CI
нужно смотреть в Actions отдельно, а не считать наличие YAML доказательством запуска.

| Изменение | Что выполнить |
|---|---|
| Код сервиса/процесса | `make check`; если изменена генерация — новый полный eval до выпуска |
| Данные/токенизатор/шаблон | подготовка с новым содержимым/config; `make flow-demo` доказывает инвалидацию; обучение зависит от роли train/eval данных |
| Новый адаптер | `verify_artifact` → полный eval ДЗ 6+7 → прежний quality_gate → Prefect release → перезапуск API |

Отказ кандидата не исправляется ретраем. Сетевые ошибки загрузки MLflow
ограничены настройками клиента; публикация, схема и quality gate не повторяются автоматически.
Локальный режим Prefect использует временный сервер и сохраняет результаты
под `.runtime`; облачный аккаунт и постоянно открытый Prefect UI не требуются.
